BMI Vitals - Fiji

This profile defines the requirements and usage of an Observation resource recording BMI vital observations. It is based on the FHIR BMI Profile and adapted as required for the Fiji Core Implementation Guide.

Mandatory elements

The following elements must be recorded:

  • status - one of the following codes (registered preliminary final amended +)
  • code.coding.system - must be http ://loinc.org
  • code.coding.code - must be 85354-9
  • category must have at miniumu one element conforming to following:
    • category.coding.system - http://terminology.hl7.org/CodeSystem/observation-category
    • category.coding.code - vital-signs
  • subject - a reference to a Fiji Patient
  • effective[x] - the date/time when the BMI was measured using one of the values below
    • effectiveDateTime (recommended for use where possible)
    • effectivePeriod - this is a time period with specific start/end over which the BMI did not change
  • valueQuantity - the BMI value measured as below (if there is no value, the dataAbsentReason must be populated with a relevant code)
    • valueQuantity.value - One numeric value
    • valueQuantity.system - "http://unitsofmeasure.org"
    • valueQuantity.code - the UCUM unit code 'kg/m2'

Other elements defined

  • dataAbsentReason - reason why no value present for this vital sign (mandatory if no value)
  • encounter - a reference to an encounter where/when the BMI measurement took place
  • interpretation - a coded concept providing interpretation for the value
  • note - any additional relevant information to be recorded

Fiji Allergy/Intolerance

Overview

The Fiji AllergyIntolerance Profile defines the minimum data elements and terminology requirements for representing a patient's known or suspected allergies and intolerances within a Fiji FHIR implementation.

The profile is based on the FHIR AllergyIntolerance resource and constrains the patient reference to the Fiji Patient profile. Where applicable, terminology bindings use Fiji-specific value sets to support consistent representation of allergy agents and clinical manifestations.

This profile can be used to represent both confirmed allergies and other adverse reactions or intolerances where clinically relevant.

Key Elements

Element Cardinality Must Support Description
code 1..1 ✓ Allergy or intolerance agent. Identifies the substance, medication, food, or other agent to which the patient has an allergy or intolerance. Bound to the Fiji Allergy Agent ValueSet with an extensible binding.
clinicalStatus 0..1 ✓ Indicates the current clinical status of the allergy or intolerance, such as active or resolved.
verificationStatus 0..1 ✓ Indicates the degree of certainty that the allergy or intolerance is valid, such as confirmed, unconfirmed, or refuted.
category 1..* ✓ Identifies the general category of the allergy or intolerance, such as medication, food, or environment.
criticality 0..1 ✓ Indicates the potential clinical impact of the allergy or intolerance, such as low, high, or unable to assess.
patient 1..1   Identifies the patient to whom the allergy or intolerance applies. The reference is constrained to the Fiji Patient profile.
onsetDateTime 0..1 ✓ Records the date and time when the allergy or intolerance was first known or began.
note 0..* ✓ Provides additional free-text clinical information about the allergy or intolerance that is not captured by the structured elements.
recorder 0..1   Identifies the practitioner or practitioner role who recorded the allergy or intolerance. References are constrained to Fiji Practitioner or Fiji PractitionerRole.
reaction 0..* ✓ Describes a clinical reaction associated with the allergy or intolerance, including its manifestations and severity.
reaction.manifestation 1..* ✓ Clinical symptoms/signs associated with the adverse reaction. Bound to the Condition (Diagnosis) Value Set using a preferred binding.
reaction.severity 0..1 ✓ Indicates the severity of the reaction, such as mild, moderate, or severe.

Terminology

The following terminology bindings are defined by this profile:

Element Value Set Description
code Fiji Allergy Agent ValueSet Based on subset of SNOMED CT concepts representing substances or products that cause allergies or intolerances, aligned with global IPS.
reaction.manifestation Condition (Diagnosis) Value Set Based on SNOMED CT concepts for "clinical finding" and "situation with explicit content" curated for International Patient Summary

The extensible binding on code allows an allergy or intolerance agent to be represented using a code outside the Fiji Allergy Agent ValueSet when an appropriate concept is not available in the value set.

The preferred binding on reaction.manifestation encourages implementers to use concepts from the Fiji Condition Code ValueSet while allowing alternative codes where appropriate.

Usage

An AllergyIntolerance instance should identify the allergy or intolerance agent using code and, where a reaction has occurred, describe the associated clinical manifestations using reaction.manifestation. The reaction.severity element may be used to communicate the clinical severity of the reaction.

Where the identity of the person responsible for recording the information is known, recorder should reference the relevant Fiji Practitioner or Fiji PractitionerRole.

No Known Allergies Representation

The recommended 'best practice' for representing 'No Known Allergies' requires a combination of the following element settings:

  1. code : should include both the SNOMED CT "716186003" and the HL7 "no-known-allergies" codings
  2. clinicalStatus : should be set to "active"
  3. verificationStatus : should be set to "confirmed" This indicates that a clinican has formally verified that status, and the use of both codings maximizes interoperability ** Note: ** Any other recorded Active allergy for the patient should negate a No Known Allergy record.
Fiji Condition

Profile of Condition (Diagnosis, Problem List item etc) as defined for Fiji Context.

This profile sets minimum expectations for an Condition resource to record, search, and fetch diagnoses or problmen-list items associated with a patient.

Mandatory elements

The following elements must be recorded:

  • code - a coded concept for the condition. The recommendation for future terminology of this element should be selected from Condition (Diagnosis) Value Set SNOMED CT Clinical Finding or Situation with Explicit Context reference sets. Current and past records may use ICD-10 AM terminology. Free text entry should only be permitted if no coded value is available or to record uncoded historic condition information.
  • subject - a reference to a Fiji Patient
  • clinicalStatus - the clinical status of the condition from one of (active, recurrence, relapse, inactive, remission or resolved)
  • category - at least one item from the extensible valueset (problem-list-item or encounter-diagnosis)

Other elements defined

  • verificationStatus - the verification status supports or declines the clincal status (unconfirmed, provisional, differential, confirmed, refuted or entered-in-error`)
  • onset[x] - the estimated or actual date or age when the condition was first observed/diagnosed
  • abatement[x] - the estimated or actual date when the condition was resolved or went into remission
  • severity - subjective severity of condition coded from condition severity valueset
  • bodySite - a coded concept specifying the part of the body used in this measurement preferred to use Body Site Value Set derived from SNOMED CT body structure concepts
  • evidence.code - coded concept for the manifestation or symptom leading to diagnosis (there may be multiple values). It is preferred that these concepts be derived from Condition Evidence Value Set SNOMED CT clinical finding or procedure sets, or LOINC lab studies or radiology codes.

Terminology

As noted above, it is intended that future deployments will use SNOMED CT valuesets for most coded concepts, but current and past information is dominantly recorded using ICD-10-AM terminology for condition codes.

Alignment with Regional IGs

The following specifications have been reviewed in development of this profile.

  • Australian Clinical Data for Interoperability Release 2
  • New Zealand Clinical Data for Interoperability 2026
  • Australian AU Core Implementation Guide 2.0.0
Fiji Diagnostic Observation

Fiji Diagnostic Observation

The Fiji Diagnostic Observation profile represents an individual observation or finding produced as part of a radiology or other diagnostic investigation. It is based on the FHIR Observation resource and provides constraints and terminology bindings appropriate for diagnostic results in Fiji.

The profile is intended to support the representation of individual diagnostic findings, including coded radiology findings, anatomical locations, performers, and component observations.

Key Elements

Element Cardinality Description
status 1..1 The status of the diagnostic observation, indicating whether the result is preliminary, final, amended, or has another applicable status.
category 1..* Classifies the observation as belonging to a diagnostic service or discipline. Bound to the FHIR Diagnostic Service Sections value set with a preferred binding.
code 1..1 Identifies the type of diagnostic finding or observation. Bound to Radiology Findings Value Set with a preferred binding.
subject 1..1 Identifies the patient who is the subject of the diagnostic observation. Restricted to FijiPatient.
effective[x] 1..1 The clinically relevant date/time or period associated with the observation.
performer 0..* Identifies the individual or organisation responsible for performing or producing the observation. Restricted to a Fiji patient, practitioner, practitioner role, or organisation.
value[x] 0..1 The result of the diagnostic observation. The type of value is determined by the nature of the observation.
dataAbsentReason 0..1 Provides a reason when a result is not available. Bound to the FHIR Data Absent Reason Value Set with an extensible binding.
bodySite 0..1 Identifies the anatomical site associated with the diagnostic observation. Bound to the Body Site Value Set with an extensible binding.
hasMember 0..* References other diagnostic observations that are related to or form part of this observation. References are restricted to FijiDiagnosticObservation.
component 0..* Represents component observations that form part of the diagnostic observation.
component.code 1..1 Identifies the type of the component observation.
component.value[x] 0..1 The result of the component observation.
component.dataAbsentReason 0..1 Provides a reason when the value of a component observation is not available.

Terminology Bindings

Element Value Set Binding Purpose
category Diagnostic Service Sections Preferred Identifies the diagnostic service or discipline associated with the observation.
code Radiology Findings Value Set Preferred Identifies the diagnostic finding or observation using relevant SNOMED CT concepts.
dataAbsentReason FHIR Data Absent Reason Extensible Provides a standard reason when an observation result is unavailable.
bodySite Body Site Value Set Extensible Identifies the anatomical or acquired body structure associated with the observation using SNOMED CT.

Diagnostic Finding Code

The code element identifies the diagnostic finding represented by the observation and is bound to Radiology Findings Value Set.

The value set is defined using SNOMED CT concepts that are both clinical findings and associated with imaging procedures:

descendant-of 404684003 |Clinical finding| AND descendant-of 363679005 |Imaging procedure|

This provides a terminology-based approach to identifying findings relevant to radiology and imaging rather than maintaining a fixed list of individual concepts.

Body Site

Where applicable, bodySite identifies the anatomical location to which the diagnostic observation relates. The element is bound to Body Site Value Set using an extensible binding.

The value set is based on SNOMED CT anatomical or acquired body structure concepts:

&lt; 442083009 |Anatomical or acquired body structure (body structure)|

This allows standard SNOMED CT concepts to be used to represent the anatomical site while allowing additional concepts where required.

Component Observations

The component element may be used when a diagnostic observation contains additional observations that are integral to the main observation. Each component must have a code identifying what is being observed and may contain either a result in value[x] or a dataAbsentReason when the result is unavailable.

Components are appropriate where the individual results form part of a single overall observation and do not need to be represented as separate resources.

Related Diagnostic Observations

The hasMember element may be used to associate the observation with other diagnostic observations. References are restricted to FijiDiagnosticObservation, supporting the representation of groups of related diagnostic findings.

For example, a diagnostic observation may use hasMember to reference separate observations representing individual findings from the same diagnostic investigation.

Missing Results

Both the main observation and its components support dataAbsentReason. This should be used when a result that would otherwise be represented in value[x] is not available, rather than leaving the reason for the missing result implicit.

The profile uses the standard FHIR Data Absent Reason value set with an extensible binding.
Fiji Healthcare Administrative Zone

Fiji Healthcare Administrative Zone

The FijiAdministrativeZone profile represents a healthcare administrative organizational unit of the Fiji Implementation Guide (IG). FijiAdministrativeZone resources combine to create a hierarchy of organizational units that describe the administrative structure of the national health provision. The profile supports a range of healthcare administrative zones including Divisions, Subdivisions, Medical Areas and Nursing Zones.

This profile is based on the FHIR Organization resource and supports the identification of healthcare organizations, classification of their roles, contact details, physical addresses, and relationships between organizational entities. This profile is to be distinguished from the FijiFacility profile which represents the organizational units are involved in the direct provision of healthcare services.

Key Elements

The following table describes the key elements defined or constrained by the FijiOrganization profile.

Element Cardinality Type Description and Usage
active 0..1 boolean Indicates whether the organization's record is in active use. This element is marked as Must Support, allowing implementations to indicate whether an organization is currently active.
type 1..1 CodeableConcept Describes the type of healthcare administrative zone (Divisions, Subdivisions, Medical Areas and Nursing Zones). The element is bound to Health Administrative Zones Value Set with a required binding.
name 1..1 string The name used to identify the organization. This is a mandatory element and must be supported by implementations.
telecom 0..* ContactPoint Contact details for the organization, such as telephone numbers, email addresses, or other supported communication channels.
address 0..* FijiAddress One or more addresses associated with the organization. Addresses must conform to the FijiAddress profile, enabling the use of Fiji-specific address structures.
partOf 0..1 Reference(FijiAdministrativeZone) Identifies the parent FijiAdministrativeZone to which this administrative zone belongs. This supports the representation of organizational hierarchies and administrative relationships.

Implementation Guidance

  • Organization classification: The type element should be used to classify the administrative zone using codes from Health Administrative Zones Value Set. The required binding mandates that any resource of this type must use the specified terminology.
  • Organization naming: The name element is mandatory and must contain the organization's name.
  • Contact information: The telecom element can carry multiple contact points, including telephone numbers and email addresses.
  • Fiji-specific addresses: All organization addresses must conform to FijiAddress, supporting consistent representation of address information in the Fiji context.
  • Organizational hierarchy: The partOf element can reference another FijiOrganization instance to represent parent–child relationships. For example, a health centre may be part of a divisional or national health service organization.

Conformance Notes

The FijiAdministrativeZone profile constrains the base FHIR Organization resource to meet the requirements of the Fiji IG.

Elements marked Must Support (MS) indicate that conformant systems must support the element as defined by the implementation guide's conformance expectations. Must Support does not, by itself, require an element to be present in every resource instance.

The name and the type elements are mandatory with 1..1 cardinality. Other elements may be absent where permitted by their cardinalities.

Fiji Healthcare Encounter

Fiji Healthcare Encounter

The Fiji Healthcare Encounter profile represents an interaction between a patient and the healthcare system in which healthcare services are provided. It is based on the FHIR Encounter resource and is intended to support the recording of clinical encounters within the scope of this Implementation Guide.

The profile constrains the patient, encounter classification, service type, participants, timing, reasons for the encounter, locations, and responsible healthcare organisation. Where appropriate, references are restricted to the corresponding Fiji profiles.

Key Elements

Element Cardinality Type / Binding Description
identifier 0..* Identifier Business identifier(s) assigned to the encounter, such as a facility encounter number or local medical record number.
status 1..1 Code Current status of the encounter, such as planned, in-progress, finished, or cancelled.
class 1..1 HL7 ActEncounterCode ValueSet Classification of the encounter, for example inpatient, outpatient, emergency, or ambulatory care.
serviceType 0..* Service Type Valueset (preferred) The type of healthcare service provided during the encounter.
subject 1..1 Reference(FijiPatient) The patient who is the subject of the encounter.
participant.type 0..* FHIR R4 Encounter Participant Type Value Set Identifies the role or function of a participant in the encounter, such as attending clinician or consultant.
participant.individual 0..1 Reference(FijiPractitioner, FijiPractitionerRole, or FijiRelatedPerson) Identifies the person participating in the encounter.
period 0..1 Period The date and time during which the encounter took place or is expected to take place.
reasonCode 0..* Encounter Reason Value Set (preferred) Coded reason for the encounter, such as a presenting complaint, clinical problem, or other reason for seeking care.
reasonReference 0..* Reference(FijiCondition or FijiProcedure) References a condition or procedure that is the reason for the encounter.
location.location 0..1 Reference(FijiLocation) The physical location where the encounter occurred.
serviceProvider 0..1 Reference(FijiOrganization) The organisation responsible for providing the healthcare services associated with the encounter.

Encounter Classification

The class element is mandatory and is bound to the HL7 ActEncounterCode Value Set. This identifies the broad setting or classification of the encounter and should be used consistently to distinguish, for example, inpatient, outpatient, emergency, and other forms of healthcare delivery.

Service Type

serviceType identifies the specific type of healthcare service being provided. It is bound with a preferred binding to Service Type Valueset, allowing implementations to use the Fiji-defined terminology where applicable while permitting other codes where necessary.

Patient and Participants

The subject element is mandatory and is restricted to a reference to a FijiPatient.

Encounter participants may be recorded using participant.type to describe their role and participant.individual to identify the participating person. Participants are restricted to a FijiPractitioner, FijiPractitionerRole, or FijiRelatedPerson.

Reason for Encounter

The reason for the encounter can be represented using either:

  • reasonCode for a coded reason that does not require a reference to another resource; or
  • reasonReference when the reason is represented by an existing FijiCondition or FijiProcedure resource.

The reasonCode element has a preferred binding to Encounter Reason Value Set.

Location and Service Provider

The location.location element identifies where the encounter occurred and is restricted to a FijiLocation.

The serviceProvider identifies the organisation responsible for the healthcare service and is restricted to a FijiOrganization.

Terminology Bindings

Element Value Set Binding
class HL7 ActEncounterCode Value Set Preferred
serviceType Service Type Valueset Preferred
participant.type FHIR R4 Encounter Participant Type Value Set Required
reasonCode Encounter Reason Value Set Preferred

Relationship to Other Resources

A FijiEncounter may be associated with other clinical and administrative resources, including:

  • Patient – identifies the patient receiving care.
  • Practitioner / PractitionerRole – identifies healthcare professionals involved in the encounter.
  • RelatedPerson – identifies other people participating in the patient's care.
  • Condition – may identify a condition that is the reason for the encounter.
  • Procedure – may identify a procedure associated with or motivating the encounter.
  • Location – identifies where care was provided.
  • Organization – identifies the healthcare organisation responsible for the encounter.

This profile is currently work in progress and may be subject to further refinement as encounter requirements for the Fiji implementation are established.

Fiji Healthcare Facility or Organization

The FijiFacililty profile represents a healthcare organization, facility, service provider, or other organizational entity involved in the delivery of healthcare within the scope of the Fiji Implementation Guide (IG). It is to be distinguished from the FijiAdministrativeZone profile which represents the organizational units are involved in healthcare administration but do not directly provide healthcare services.

This profile is based on the FHIR Organization resource and supports the identification of healthcare organizations, classification of their roles, contact details, physical addresses, and relationships between organizational entities.

Every FijiFacility resource must include a national facility identifier issued or recognized within the Fiji healthcare context. This identifier is represented by the identifier[nationalOrganizationId] slice and uses the identifier system:

https://fhir.health.gov.fj/identifier/facility

The national facility identifier provides a consistent means of identifying organizations across systems and supports interoperability between healthcare applications and services.

The profile supports a range of healthcare entities, including hospitals, health centres, clinics, nursing stations, laboratories, and other healthcare service providers. Organizations may be associated with a parent organization to represent organizational hierarchies, such as a health facility belonging to a larger healthcare administration.

  • Organization naming: The name element is mandatory and must contain the organization's name.
  • Contact information: The telecom element can carry multiple contact points, including telephone numbers and email addresses.
  • Fiji-specific addresses: All organization addresses must conform to FijiAddress, supporting consistent representation of address information in the Fiji context.
  • Organizational hierarchy: The partOf element can reference another FijiOrganization instance to represent parent–child relationships. For example, a health centre may be part of a divisional or national health service organization.

The FijiFacililty profile constrains the base FHIR Organization resource to meet the requirements of the Fiji IG.

Fiji Healthcare Procedure

Fiji Healthcare Procedure Profile

The FijiProcedure profile defines how the FHIR Procedure resource is used to record current and historical procedures performed on or for a patient within the Fiji Healthcare Implementation Guide.

A procedure is an activity performed on, with, or for a patient as part of the provision of healthcare or support services. Examples include surgical and diagnostic procedures, endoscopic procedures, biopsies, counselling, physiotherapy, personal support services, adult day care services, non-emergency transportation, home modifications, and exercise.

Procedures may be performed by healthcare professionals, service providers, friends or relatives, or by the patient themselves.

This profile constrains the standard FHIR Procedure resource to support consistent recording of procedure details, including the procedure performed, its status, the patient, the associated encounter and service request, the performers, the reasons for the procedure, the anatomical site, the outcome, and any complications.

Implementation Guidance

Procedure Identification and Classification

The code element is mandatory and identifies the specific procedure. Implementations should use appropriate codes from the preferred $proc-code-ips-vs value set. The optional category element provides a broader classification using $proc-cat-vs.

Status and Timing

The status element is mandatory and indicates the lifecycle state of the procedure. The performed[x] element records the procedure's timing when available. Implementations should distinguish between a procedure that was completed, is in progress, or was not performed, using the appropriate status and timing information.

Patient, Encounter and Service Request References

The subject element must reference a FijiPatient. Where applicable, encounter links the procedure to a FijiEncounter, while basedOn links it to one or more FijiServiceRequest resources.

These references support traceability between the patient, the clinical encounter, the requested service, and the procedure performed.

Performers

The performer element records those involved in performing the procedure. The performer.actor reference is constrained to the following Fiji profiles:

  • FijiPractitioner
  • FijiPractitionerRole
  • FijiOrganization

Where an appropriate terminology exists, coded pathology observations should use internationally recognized terminology such as LOINC for laboratory tests and SNOMED CT where appropriate. Results expressed as quantities should use UCUM for units of measure.

Pathology Panels

A pathology panel may be represented as a higher-level FijiPathologyObservation with hasMember references to the individual results.

For example, a lipid panel could be represented as:

FijiPathologyObservation
  code: Lipid panel
  hasMember:
    - Total cholesterol
    - HDL cholesterol
    - LDL cholesterol
    - Triglycerides

Each member is itself a FijiPathologyObservation and can contain its own result, interpretation, reference range, and specimen.

This approach allows individual pathology results to be independently referenced and exchanged while retaining their relationship to the overall panel.

Components

component should be used when multiple measurements form part of a single observation rather than being independently represented results.

For example, an observation representing a blood pressure measurement can contain systolic and diastolic blood pressure as components. In contrast, a laboratory panel such as a lipid panel is generally better represented using hasMember, with each analyte represented as a separate observation.
Fiji Patient

Fiji Patient Profile

The FijiPatient profile defines the representation of a patient in Fiji healthcare information systems. It builds on the FHIR Patient resource and establishes requirements and guidance for recording patient identity, names, demographic information, administrative geography, cultural affiliation, and other relevant personal characteristics.

The profile supports consistent patient identification across healthcare settings through a mandatory national health number, while allowing additional identifiers such as national identification numbers and facility-specific medical record numbers.

It also supports Fiji-specific naming conventions through FijiHumanName, administrative zone information through FijiAdminZone, and iTaukei cultural and genealogical affiliation through FijiITaukeiAffiliation. Additional extensions support nationality, religious affiliation, occupation, and ethnicity.

The profile encourages the use of Fiji-specific resource profiles where available, while retaining compatibility with standard FHIR resources.

Scope and Usage

FijiPatient is intended to represent a person receiving or having received healthcare services within the scope of the Fiji Implementation Guide.

It supports:

  • Identification of patients using a mandatory national health number and other applicable identifiers.
  • Recording of official and usual names, including culturally appropriate naming conventions.
  • Representation of health administration zones relevant to the patient's care.
  • Recording of iTaukei cultural and genealogical affiliations when applicable.
  • Recording of nationality, religious affiliation, occupation, and ethnicity where known and appropriate.
  • Recording of basic demographic information, including gender and date of birth.
  • Recording of patient addresses, languages, healthcare providers, and managing organizations.
  • Linking to other records concerning the same person, including related persons.

Optional demographic and cultural information should be recorded only when available, relevant, and appropriate for the intended healthcare purpose.

  • Tokatoka (family)

The patient-nationality extension records the patient's nationality using a coded country value. The profile requires the extension's code subextension to use the ISO country value set.

Naming Requirements

All patient names must conform to FijiHumanName. At least one name must be recorded.

The profile includes the following invariant:

pac-pat-1: At least one name must have use = usual or use = official.

This invariant has warning severity. It encourages implementations to identify either a usual name for everyday use and display, or an official name for formal identification, without making either specific name-use category an unconditional validation requirement.

Where both names are available, implementations should preserve their distinct purposes. The usual name is generally appropriate for routine display, while the official name supports formal identification and medico-legal processes.

Patient Identification

The profile requires at least one patient identifier and mandates exactly one identifier slice for the national health number.

The national health number identifier must use the following system URI:

http://fhir.health.gov.fj/identifier/national-health-number

The identifier's value is mandatory. Other identifiers may be recorded using their appropriate identifier systems, including national identification numbers and facility-specific medical record numbers.

Identifiers should be preserved with their assigning system so that values originating from different identifier namespaces are not incorrectly treated as equivalent.

Demographic Information

The profile supports the recording of gender and date of birth, with both elements marked Must Support.

Date of birth may be uncertain or estimated. Where an estimated date of birth is recorded, the BirthDateEstimatedIndicator extension can indicate that the date is estimated rather than confirmed.

Addresses must conform to FijiAddress, allowing address information to follow the Fiji-specific representation defined by the Implementation Guide.

Patient languages are recorded through communication, supporting appropriate communication and continuity of care.

Care Providers and Organizational Responsibility

The generalPractitioner element supports references to practitioners and practitioner roles. The profile distinguishes these reference types through slicing:

  • generalPractitioner[practitioner] references a FijiPractitioner or standard Practitioner.
  • generalPractitioner[role] references a FijiPractitionerRole or standard PractitionerRole.

The managingOrganization element identifies the Administrative Zone organizational unit (Division, Subdivision, Medical Area or Nursing Zone) responsible for the patient and should reference a FijiAdministrativeZone.

Implementations should prefer Fiji-specific profiles where available, while permitting standard FHIR resources for interoperability.

Must Support and Conformance Notes

Elements marked Must Support indicate that implementations are expected to support the element in accordance with the Implementation Guide's conformance expectations. Must Support does not, by itself, mean that the element must contain a value in every instance.

The following elements are explicitly marked Must Support in the supplied profile:

  • National health number identifier system and value
  • Gender
  • Date of birth
  • Estimated date-of-birth indicator extension
  • Occupation extension
  • Ethnicity extension

The profile also defines mandatory cardinalities for identifiers, identifier system and value, the national health number slice, and patient names. These cardinality requirements must be distinguished from Must Support expectations.

Implementation Considerations

  1. Patient identity: Ensure that the mandatory national health number is recorded using the prescribed identifier system URI.
  2. Name handling: Use FijiHumanName and distinguish official and usual names where the information is available.
  3. Administrative geography: Reference FijiAdministrativeZone in managingOrganization for healthcare administration and service geography.
  4. Cultural affiliation: Use FijiITaukeiAffiliation for relevant iTaukei cultural and genealogical information, without substituting administrative geography for traditional affiliation.
  5. Terminology: Apply the required ISO country value set for nationality and the specified extensible terminology binding for religious affiliation.
  6. Terminology development: Complete the occupation and ethnicity value set definitions before imposing more specific terminology conformance requirements.
  7. Data quality: Represent estimated dates of birth explicitly and preserve identifier systems.
  8. Interoperability: Prefer Fiji-specific profiles for practitioners, practitioner roles, organizations, addresses, and related persons when available, while maintaining compatibility with standard FHIR resources.
  9. Privacy and appropriate use: Collect and disclose cultural, religious, and other personal information in accordance with applicable privacy, governance, and healthcare requirements.

Fiji Practitioner Profile

The Fiji Practitioner profile represents a healthcare practitioner involved in the delivery of healthcare services within Fiji. It supports culturally appropriate naming conventions while preserving the regulatory and medico-legal identity requirements necessary for clinical documentation, healthcare information exchange (HIE), and practitioner identification.

The profile uses the FHIR Practitioner resource and supports professional identifiers, registered and commonly used names, contact information, professional qualifications, and languages used by the practitioner. An optional iTaukei affiliation extension supports culturally appropriate representation of clan affiliation where applicable.

At least one professional identifier and exactly one official name are required. A usual name may be recorded when the practitioner is commonly known by a different name in clinical or community settings.

Implementation guidance

  • Professional identity: Implementations should use the medical registration identifier when one is available. The profile currently permits other identifiers and does not require the medical registration slice to be populated.
  • Name handling: The official name should reflect the practitioner's registered or licensed identity. The usual name supports respectful, culturally appropriate communication without replacing the official name.
  • Cultural affiliation: Record the iTaukei affiliation extension only where applicable and appropriate. It is optional and should not be used as a substitute for practitioner identity or professional registration.
  • Qualifications: Record each qualification separately, using an appropriate coded qualification where available. A Fiji-specific qualification value set may be introduced in a future version.
  • Communication: Record the languages the practitioner can use to support appropriate patient communication and care coordination. A minimum communication language is not currently required.
  • Contact information: Use telecom and address for professional contact details and practice or correspondence locations, subject to applicable privacy and data governance requirements.

Scope and future considerations

The following items are identified for future development and are not mandatory constraints in the current profile:

  • Require at least one medical or other professional registration identifier through a dedicated identifier slice.
  • Bind qualification.code to an appropriate Fiji-specific value set.
  • Require at least one practitioner communication language.
  • Consider a dedicated displayName extension if a consistent preferred-name display mechanism is needed across electronic health record systems and HIE services.

This profile is intended to provide a consistent representation of healthcare practitioners across Fiji's healthcare systems while supporting professional accountability, interoperability, and culturally appropriate care.
